# Project 2. Steps taken

The project followed the phases of [`ROADMAP.md`](../../ROADMAP.md). Dates and figures
come from [`notes/PROGRESS.md`](../../notes/PROGRESS.md) and the git history.

## Step 1: setup (done)

dtk-template configured for `RM7P4F`; first build of an identical `main.dol` with
everything in assembly. Two analysis fixes were needed (`.sbss2`, a function split in
two by mistake, see [Setup](01-setup-and-toolchain.md)). Private GitHub repository,
template kept as `upstream`.

**Lesson**: get the all-assembly build to `main.dol: OK` first. Every later change is
checked against it.

## Step 2: compiler identification (mostly done)

Probes and fuzzing as described in [Setup](01-setup-and-toolchain.md); the exact GC
3.0 version is still a working hypothesis.

**Lesson**: test compilers on several small, varied functions before decompiling
anything big, and keep a written list of what is proven and what is assumed.

## Step 3: splitting (in progress)

Region map of the DOL in [`notes/SPLITS.md`](../../notes/SPLITS.md): game code first,
then the Wii SDK, the runtime (`Runtime.PPCEABI.H`), the C library (MSL_C), MetroTRK
(debugger kernel). Library units were bounded with the reference projects (same
libraries, known file order and sizes). Game units are bounded by their static
initializers: almost every game file includes a header with a global `(0, 1, 0)`
vector, so each one ends with a `__sinit` function and a `.ctors` entry.

**Lesson**: `main.dol: OK` holds for **any** consistent split, so a split proves
nothing about real file boundaries until the unit is decompiled and matches.

## Step 4: comparison tooling (done)

objdiff report generated by every build, `objdiff.json` for the GUI, CI running the
full check on every push (with the DOL in a private container image, never in the
repository), progress charts drawn locally because the project stays private (no
decomp.dev).

## Step 5: library code (mostly done)

On 2026-10-12, Runtime.PPCEABI.H was the pilot: 9 units matching, mostly code reused
from CC0 projects (mscharged-decomp, Twilight Princess). Then MSL_C (59/59, with the
two compiler versions), MetroTRK (29/29), and the Wii SDK, which reached 172 of 179
units matching. Each reused file is logged with its source project, commit and
license in [`notes/PROVENANCE.md`](../../notes/PROVENANCE.md). Some SDK files were
newer than any reference and were completed by decompiling the differences.

A useful trick of that phase: unsplit SDK regions were found by searching the
reference clones for the same **sequence of function sizes**.

**Lesson**: libraries are shared between games; reuse a matching implementation when
its license allows, but check every function against *this* binary, because versions
differ.

## Step 6: game code (current)

Started on 2026-10-15. Smallest units and call-tree leaves first, one unit per
commit. The Entity class family (from RTTI names such as `Entity_Prop`), script and
state callbacks, camera influences, UI screens... Shared headers grew in
`include/game/` (`Entity.h`, `unk_vec3.h`...). At the time of writing: 119 game units
split, 84 linked, and about 25 % of all code matched (most of it the SDK).
Near-misses stay NonMatching with their gap in [`TASKS.md`](../../TASKS.md).

**Lesson**: each solved difficulty becomes a line in
[`notes/MATCHING.md`](../../notes/MATCHING.md); later units reuse it.
